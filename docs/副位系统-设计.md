# 副位（Socket）系统 · 设计蓝图

> 状态：**v1 已实现，等待实测**（2026-10-26）
> 已落地：`sockets` 组件、槽位表、镶嵌台方块（无界面，右键交互）、铜芯充能 +20%（上限 +60%）、tooltip
> 未做：玫瑰金自修、海晶、幻翼、石英；拖拽式界面（视手感再定）

> 关联：`README.md` 的材料阶梯、`skill/` 下的技能系统

## 0. 一句话

每件装备自带若干**副位**，把**另一件装备**放进去，副位装备的**特性**叠加到主装备上；副位装备的**数值**（护甲、攻击力）一律不生效。

不是新造"宝石物品"，副位里塞的就是现有装备——铜合金件、海晶件、玫瑰金件，都能当"宝石"用。

---

## 1. 参考与取舍

参考的是 Trinkets 系列的**交互直觉**：

- [emilyploszaj/trinkets](https://github.com/emilyploszaj/trinkets)：Fabric 的饰品 mod/API，在物品栏里加一块饰品槽面板，槽位分组数据驱动（手 / 胸 / 头 / 脚 / 副手之类），物品靠数据声明自己"可佩戴"，玩家拖进去就生效、随时能取出来换
- [trinkets-updated](https://modrinth.com/mod/trinkets-updated)：它的社区维护版

我们**借**的是这三点：一个槽 → 放进去 → 立刻生效、随时可换、槽位数量/类型由规则决定。

我们**不借**它的实现方式（玩家身上挂饰品栏），原因：

|  | Trinkets 的做法 | 我们的做法 |
|---|---|---|
| 槽挂在 | 玩家身上 | **装备物品**上 |
| 需要改物品栏 GUI | 要（mixin InventoryScreen） | 不要 |
| 需要玩家数据持久化 + 同步 | 要 | 不要（数据就在物品里） |
| 能不能做"星辉剑多槽/副剑" | 不能 | **能** |
| 换装体验 | 拖一下就换 | 通过镶嵌台（v1）/ 配方（v0.5） |

一句话：**槽位跟着装备走，不跟着玩家走**。这也正好对上你说的"星辉剑可以有多个槽位，装别的副剑"。

## 2. 数据模型

### 2.1 组件

```
kalioupo_equipment:sockets  :  List<String>   （物品 id，可空，最多 5 条）
```

- 只存 **id**，不存完整 ItemStack：
  - 副位装备不磨损、不附魔、不参与堆叠，id 足够表达
  - 体积小、同步便宜、没有"物品副本"导致的复制/丢失问题
- 槽位上限**不写进组件**，由物品 id 查代码常量表（防止被数据包/指令改到 99 槽）
- 组件缺省 = 空列表 = 没有副位内容，旧存档天然兼容

### 2.2 副位物品的判定

不是白名单硬编码，而是一个"可作副位"的标签：

```
data/kalioupo_equipment/tags/item/socketable.json   → 我们的全部装备
```

以后想让某个新物品能当副位，加进标签即可。

## 3. 槽位阶梯

| 档位 | 槽位数 |
|---|---|
| 碳钢 / 铜合金 / 石英钢 / 玫瑰金 / 海晶 / 紫水晶 / 幻翼 | 1 |
| 黑曜石 | 2 |
| 基岩强化 | 3 |
| 回响 | 4 |
| 星辉 | **5** |

星辉给 5 槽，是"万剑合一"的实现方式：玩家自己往里拼，而不是我们预设好。

> **已定：碳钢档也给 1 槽**。理由是开局就能用——玩家还没挖到钻石、但做出一把紫水晶剑时，可以立刻塞一块铜合金进去加速充能（紫水晶的充能体感确实偏慢）。
> 星辉的 5 槽是"万剑合一"的落点，先给 5，视手感再收。

## 4. 特性表（副位放什么 → 主装备得到什么）

**红线：只给手段/特性，不给攻击力、护甲、最大生命这类数值。**

| 副位物品 | 特性 | 生效条件 | 备注 |
|---|---|---|---|
| 铜合金件（任意） | 技能充能速度 **+20%** | 主装备为紫水晶/回响/星辉剑 | 多件可叠，**上限 +60%** |
| 石英钢件（任意） | 命中额外 **+2 伤害**，但主武器每次攻击**多耗 1 点耐久** | 主装备为武器 | **支线，最低优先级**（实战基本都拿主力武器） |
| 玫瑰金件（任意） | **缓慢自修**：每 20 秒回 1 点耐久 | 主装备有耐久 | 最接近"修复宝石" |
| 海晶头盔 / 靴子 | **水下呼吸 + 水下不减速** | 穿戴主装备时 | 用原版效果实现，视觉直观 |
| 海晶件（任意） | 对**水生生物 +15% 伤害** | 主装备为武器 | 水中 / 两栖类 |
| 幻翼件（任意） | **坠落伤害 -50%** | 穿戴主装备时 | 和幻翼套的滑翔互补 |
| 基岩 / 回响 / 星辉件 | 暂不开放（避免数值化） | — | v2 再定 |

副位装备的护甲值、攻击力、套装效果**全部不生效**——这是"不加数值"的保证。

## 5. 交互

### 5.1 v0.5（先验证手感，不做 GUI）

工作台的**特殊配方**（data-driven，26.3 已确认支持：`crafting_special_repairitem` 就是一个空字段的 JSON，照这个形状写）：

```
主装备 + 副位装备  →  主装备（追加第一个空槽）
```

限制：**不能取出**、槽满了配方不匹配。先只验证"效果爽不爽"。

### 5.2 v1（镶嵌台）

新方块 **镶嵌台**：右键打开界面。

```
┌──────────────┐
│  [主装备槽]   │   ← 放要镶的装备
│              │
│  副位 1 ～ 5  │   ← 显示当前副位内容，可拖入 / 拖出
└──────────────┘
```

- 没有"输出槽"，也没有合成动作——**主装备本身就是唯一数据源**
- 每次槽位变动立刻写回主装备组件（关界面也不会丢）
- 取出 = 直接从副位槽拖回背包，装备上的对应条目移除
- 缺点是要写菜单 + 界面（约 400 行），但我们已经有两套界面模板（背包、熔炼炉）可以照抄

### 5.3 为什么不做"玩家身上的副位栏"

你的日常用法（家在铜 / 下海换海晶）用物品槽完全能做到：**换一把主武器，等于换一整套副位**。而玩家级饰品栏会挡住"星辉剑多槽"这个核心诉求，且实现成本高一个数量级。

## 6. 效果实现点（代码落点）

| 特性 | 落点 | 难度 |
|---|---|---|
| 充能速度 | `AmethystSkill.tickServer` 的 +1/次 改成 +倍率 | 低 |
| 自修 | 新 `SocketEffects` 每 20 tick 扫装备栏 | 低 |
| 水下呼吸 / 不减速 | 给 `WATER_BREATHING` + `DOLPHINS_GRACE` 效果 | 低 |
| 坠落减伤 | `ServerLivingEntityEvents.ALLOW_DAMAGE` + `IS_FALL` | 低 |
| 水生伤害 | `ALLOW_DAMAGE` 里判断目标类型 | 低 |
| 石英爆发 | 伤害 +2，并额外扣主武器耐久 | 中（要拿到攻击上下文） |
| 副剑加强技能（v2） | 星辉剑槽位里放同类武器 → 提升技能等级 | 中 |

## 7. 平衡原则（我的决定）

按你说的"后面两点我结合并决定"：

1. **不做必修**：不镶副位没有任何惩罚，也不影响主线推进。副位是"锦上添花"，数值上刻意给得克制。
2. **舒适优先**：副位物品**不磨损**、可随时取出、镶嵌台不消耗经验。玩家的资产永远能拿回来。
3. **同类叠加上限 3 层**（充能 +60% 封顶），防止"全铜剑"变成唯一解。
4. **副位装备是消耗品**：镶进去就留在里面（取出才回来）。这样它才算材料的去处——想做三把不同用途的剑，就得做三份铜。

## 8. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 菜单复制 / 丢失物品 | 玩家资产 | **主装备是唯一数据源**，每次变更立即写回；v0.5 先不碰 GUI |
| 组件被数据包/指令改出 99 槽 | 平衡崩 | 槽位上限只从代码常量读，组件只存内容 |
| 效果叠加过强 | 平衡 | 同类上限 3 层，且只给特性 |
| 26.3 特殊配方注册方式 | 编译/加载风险 | 已确认是 data-driven JSON（`crafting_special_repairitem` 空字段即可） |
| 旧存档兼容 | 无 | 组件缺省 = 空列表 |
| 界面里取走主装备时副位物品去哪 | 物品纠纷 | v1 规则：副位跟着主装备走，主装备离开界面时一起写回 |

## 10. 已拍板（2026-10-26）

1. **槽位只存物品 id** —— 副位装备不参与战斗，只当加成，id 足够，也就没有副本/复制风险
2. **镶嵌台做成方块**（有工坊感，沿用熔炼炉的先例）
3. **碳钢档也给 1 槽**（开局就能配合紫水晶剑加速充能）
4. **先做铜的充能速度**，其次玫瑰金的缓慢自修
5. **石英的爆发特性降为支线**，最后再做（实战基本不会切到石英武器）
6. **1.1.0 冻结为稳定正式版**；副位系统走独立版本号，桌面只保留「稳定版 + 最新版」
